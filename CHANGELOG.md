# Changelog

All notable changes to this project are documented here.

The format is based on [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Versions 0.0.1 to 0.4.0 predate the public repository, so they have no tag or comparison links here.

## [Unreleased]

Preparation of the public release.

### Added

- `SECURITY.md`: how to report a vulnerability privately, the supported versions and the scope.
- `CODE_OF_CONDUCT.md`: the Contributor Covenant 2.1.
- Issue forms for bug reports and feature requests, a pull request template, and a contact link that sends security
  reports to GitHub's private vulnerability reporting.

### Changed

- Meddle S.r.l. is named as the copyright holder in the SPDX headers, `NOTICE`, the package manifests and the rebuilt
  manual PDFs.
- `CONTRIBUTING.md` is rewritten for outside contributors and states the project's ten ground rules.
- The README, the guides under `docs/` and these release notes are rewritten for a public audience, with links only to
  documents in the repository.
- Commit messages no longer need a task id in their body: `make commits` and the commit check of a pull request in CI
  check only the Conventional Commits subject, as the `commit-msg` hook already did. The `plan` and `adr` commit scopes
  are gone with the documents they named.
- The held-out and Von threshold records moved to `tools/eval/records/`, the MetroPT-3 first-month statistics to
  `data/metropt3-first-month-stats.json` (generated by `scripts/data/metropt3_stats.py`) and the README screenshots to
  `docs/img/`.
- `NOTICE` states that no MetroPT-3 rows are committed, only derived statistics.

### Removed

- The internal planning documents: the implementation plan, the architecture decision records, the specification, the
  roadmap and the release checklist. The public guides under `docs/` describe the system as built.

## [0.4.0] - 2026-09-24

The dashboard, the Compose stack end to end, CI, and live and recorded evaluation runs.

### Added

- **Dashboard** (`apps/frontend`, React, Tailwind CSS and shadcn/ui, served by nginx): light and dark themes, a status
  bar with the simulated clock and the active backend, the live signal recorder with downsampling, a machine-state strip
  and reference-window overlays, the simulation panel (play, pause, speed, jump-to presets, fault injection, clear and
  reset), the alerts feed with the decision sheet, the tickets tab and the review queue with close-as-correct or wrong,
  the cost panel and the suspect-events tab. The initial JavaScript is 179 kB gzip.
- **Browser tests** in two modes: against a scripted fake backend (`make e2e-mock`, `make e2e-perf`) and against a
  running stack (`make e2e`), with accessibility checks and a streaming budget.
- **Stack smoke tests**: `scripts/smoke.sh` with `make smoke` (the CI stack with the mock decision service),
  `make smoke-quickstart` (the README quick start with the rules backend) and the opt-in `make smoke-live`.
- **CI jobs** for the stack, the quick start, the evaluation's smoke profile and the next broker version.
- **Evaluation**: live Von and LLM runs behind `--confirm-live` with a printed cost plan, cassettes that record and
  replay answers, the `full` profile over the whole MetroPT-3 recording, scoring of a running stack from its database
  (`make eval-stack`), and a threshold sweep that chooses Von's gate pair as pre-registered (`make eval-sweep`).
- **A sealed held-out set** of six scenarios, drawn by a rule fixed in advance from days that no scenario, slice or
  document had used, which the harness runs once only
  ([tools/eval/records/heldout-seal.md](tools/eval/records/heldout-seal.md)).
- **Persistence gate**: an episode is first decided once its symptom has kept firing for `GATE_PERSIST_SIM_MIN`
  simulated minutes (default 1), and every decision reports how long its evidence held.
- `make reset-db`, the README consistency test, and `make manual-scanned`, which writes a skewed, noisy, image-only copy
  of the realistic manual for OCR experiments (not committed).

### Changed

- Von has its own gate pair, `VON_GATE_REVIEW_MIN_CONFIDENCE` and `VON_GATE_TICKET_MIN_CONFIDENCE`, because its
  probability is on a different scale from the rules backend's confidence. It defaults to the pre-registered choice,
  0.65 / 0.85 ([tools/eval/records/von-thresholds-choice.md](tools/eval/records/von-thresholds-choice.md)), whatever the
  global pair is set to; the rules and LLM backends keep 0.60 / 0.85.
- The Von request quotes the manual's distinctions between candidate causes in its Choice criteria.
- Detection and the decision state describe idle pressure decay by kind of hour, the motor's answer to a load request
  and the separator's recovery after cut-out; a ramp injection can anchor at the moment its guard starts to hold.
- The evaluation binds the F2 and F3 failure windows from their data onsets and measures lead time from the credited
  span.

### Fixed

- The backend survives Postgres closing a pooled connection, and a failed push no longer half-applies episodes and
  tickets.
- The LLM backend sends probabilities and support as lists.
- Several dashboard fixes: replay markers drawn once, readable tab and alert labels, the recorder seeded when the page
  opens on a paused replay, and the speed slider kept in step with keyboard input.

### Evaluation

The rules backend on the whole MetroPT-3 recording (1,516,418 samples, 158.1 machine-days free of labelled failures)
catches none of the four failures (0 of 4): the one ticket it opens inside a failure window, during F4, names a fault
other than the air leak. It opens 0.063 false tickets per machine-day at ticket level and 0.209 at review level. At
detection level, a suspect event inside the credited span, it passes 9 of the 10 core scenarios, 5 of 6 positives and
all four MetroPT-3 failures; its diagnosis stays at 4 of 10 and 0 of 6. These figures are in-sample: the rules were
designed after looking at the four failures, and the detection-level criterion and later design decisions were chosen
after the in-sample results had been seen. On the held-out set, the one clean measurement, the rules backend diagnosed
0 of 4 positives and detected 3 of 4, and it opened no non-benign ticket on either negative day, one of which raised a
suspect event ([tools/eval/records/heldout-final-run.md](tools/eval/records/heldout-final-run.md)). Von was evaluated;
its results are not published pending the vendor's terms.

### Known limitations

- The README quick start with the rules backend opens no review item: the decision on the 5 June 2020 leak stays below
  the review threshold and is gated to `log`. `make smoke-quickstart` exits 3 at that check, and the CI `quickstart`
  job, which runs the same script, fails there too.
- The rules backend catches none of the four MetroPT-3 failures on the whole recording (in-sample).
- The failure windows are this project's resolution of the dataset's failure table ([docs/dataset.md](docs/dataset.md));
  figures that depend on them are provisional.
- Two tests are occasionally flaky: the gateway's health-probe shutdown under `-race` and a recorder timer teardown.

## [0.3.0] - 2026-09-24

The init service and the backend's diagnosis pipeline.

### Added

- **init** (`tools/init`): readiness waits and exit codes by step, the migration runner, the MetroPT-3 download with the
  UCI fallback and the `SHA256SUMS` check, PDF extraction (layout, sections and ruled tables), chunking with section
  references, the deterministic catalog builder, the optional LLM catalog structurer with a deterministic fallback,
  ONNX embeddings with a hash-verified model cache, an idempotent pipeline with an ingest report, the init image, an
  extraction-quality gate on the committed manuals and `fdp-init export-catalog`.
- **Backend** (`apps/backend`): telemetry ingest with one-minute aggregates and native alarm transitions; detection
  (signal roles, machine state, guards, cycle tracking, baselines and the rules that raise suspect events); retrieval
  (the catalog's signal-move match and hybrid full-text and pgvector search); the rules, LLM and Von decision backends
  with a cost ledger; the confidence gate; episodes, tickets and the review lifecycle; the heartbeat and status
  publisher; the read-only ground-truth overlay; the REST routes and the WebSocket hub.
- **Evaluation runner** (`tools/eval`): the in-process pipeline host, the `run` command with JSON and Markdown reports,
  the core-10 gate, an explicit tuning list and a synthetic ambient-temperature lane on every replay.
- Make targets for the init test layers: `test-init`, `test-init-integration`, `test-init-e2e` and `test-init-quality`.

### Changed

- `make ci` also runs the init container end-to-end test.
- Detection floors its level bands and its erratic-signal test at sensor accuracy, and a suspect event carries its full
  observation set.

### Fixed

- Both committed manuals print each cause's signal moves again, which init needs to build the catalog; the PDFs, their
  manifest and the reference catalog were rebuilt.
- The `suspect-event` schema describes `observations` as the full observation set detection sends.

### Evaluation

With the rules backend, on the catalog extracted from the realistic manual and on the reference catalog alike, the
diagnosis passes 4 of the 10 core scenarios and 0 of 6 positives, and catches none of the four MetroPT-3 failures;
every negative, abstention and depot scenario passes. These figures are in-sample. The detection-level results and the
changes that followed them ship with 0.4.0.

### Known limitations

- The rules backend diagnoses none of the positive scenarios at ticket level (in-sample).
- The failure windows the figures depend on are provisional (see 0.4.0).

## [0.2.0] - 2026-09-24

The contracts, the simulator and gateway, the ground truth, the Compose stack and the evaluation harness's foundations.

### Added

- **Contracts** (`packages/contracts`): 38 versioned JSON Schemas with generated TypeScript types, validators and topic
  builders, a drift check, and the register map generated for JSON, TypeScript and Go (16 signals, 27 evaluable
  controller alarm bits); see [packages/contracts/VERSIONING.md](packages/contracts/VERSIONING.md).
- **Database**: plain-SQL migrations for schemas, ground truth, manual chunks, the catalog, telemetry, diagnosis, cost
  and system state, behind three login roles (`app_rw`, `gt_rw`, `eval`), applied by `packages/db-migrate`.
- **Ground truth** (`packages/ground-truth`): the resolved MetroPT-3 failure table, 9 presets and 9 injection
  definitions.
- **Mock decision services**: mock TypeSafe and Anthropic servers with SDK compatibility tests for Node and Python, and
  the embedding pin with a reference fixture.
- **Simulator and gateway** (`services/modbus`): CSV replay with a seekable cursor and gap detection, the simulated
  clock, a read-only Modbus TCP server, the fault-injection engine (seven primitives with time envelopes), the CTRL-7
  alarm evaluator with a deterministic ambient-temperature model, the MQTT control plane, and the gateway that polls the
  device and publishes telemetry; distroless, non-root images.
- **Stack**: the Mosquitto broker image with an ACL rendered from the topic contract, the Compose topology with
  development and CI overrides, `make up`, `down`, `reset` and `compose-check`, and the MetroPT-3 slice definitions with
  a verified fetch script, so `make fixtures` cuts all 16 slices without committing a single row.
- **CI**: the GitHub Actions workflow with composite toolchain and dataset actions, and Dependabot.
- **Evaluation harness** (`tools/eval`): the MetroPT-3 replay engine, 21 evaluation scenarios with their schema and
  loader, the metrics library (ticket matching, precision and recall per fault, lead time, false tickets per
  machine-day, abstention, cost), the `validate` command, and TypeScript ports of the injection primitives and the
  alarm evaluator, proven equal to the Go simulator by a Docker parity test.

### Evaluation

At signal level, 10 of 10 scenarios reach the broker as expected through the simulator and the gateway, and the Docker
parity test produces identical alarm lists on both sides over the F3 leak. No model was called in this release.

## [0.1.0] - 2026-09-20

The repository foundation and the fictional CAU-7 manual.

### Added

- **Foundation**: the pnpm, uv and Go workspaces; the lint gates (SPDX headers, ground-truth paths, environment
  variables, REUSE order and import boundaries in all three languages); the REUSE-compliant licensing layout; the
  hashed brand blocklist scanner (`fdp-blocklist`); the dependency licence audit (`fdp-checks licenses`); Conventional
  Commits checks with opt-in git hooks; the `check`, `check-int` and `ci` gate levels behind `make`; and
  `scripts/foundation-smoke.sh`.
- **Manual sources** (`manual/spec/`): 16 signals (15 mapped to MetroPT-3 columns), 25 settings, 35 controller messages
  with 27 machine-evaluable trigger bits, 13 maintenance tasks and a fault catalog of 17 conditions and 39 causes
  (3 benign) with plain-words signal moves; JSON Schemas and a strict validator; normal bands derived from the first
  MetroPT-3 month only; figures and chapter templates.
- **Manual build** (`tools/manual-build`): the YAML to HTML to PDF pipeline with WeasyPrint, clean and realistic
  variants, embedded IBM Plex fonts, a pinned build container with a fixed `SOURCE_DATE_EPOCH`, a build manifest and the
  acceptance checks ([docs/manual.md](docs/manual.md#acceptance-checks)). Both PDFs are committed in `data/manual/`
  (48 and 45 pages) with the reference catalog `tools/eval/fixtures/catalog.json`.

### Changed

- `make check-manual` takes an optional `REBUILT_DIR`, so a container rebuild can be compared the way CI does.

### Fixed

- `make ci` on macOS: WeasyPrint could not load its native libraries, so a manual check errored and the manual-build
  tests skipped. The Makefile's `WEASYPRINT_ENV` points them at the Homebrew prefix; it is ignored on Linux.
